# 教学课件工作流推广计划

## 目标

先邀请 5 位教师或助教完成最小试用，记录安装、示例成功和实际制作结果；这只是招募目标，不是已达成的用户数。确认首次使用路径可行后，再扩展到 10–20 位试用者和更多自愿授权的案例。

## 核心定位

**讲义 + 标准 PPT → 可复用、可审核的教学课件工作流。**

它帮助教师保留课程知识、既有版式、授课备注和可编辑内容，并把反馈用于后续章节复用。模型负责理解与设计，教师保留最终审核权。

不要宣传为“Word 自动转 PPT”“一键生成高质量课件”或“完全无人审核的教学系统”。这些说法与当前能力和验证范围不一致。

## 优先用户

1. **高校教师和助教**：有讲义、标准课件和后续章节制作需求的人。
2. **课程教研团队**：需要检查知识覆盖、版式一致性和交付过程的人。
3. **培训与教学设计者**：希望把密集材料改造成情境任务、问题和点击揭示分析的人。

首轮只选一个主要入口：高校教师/助教。受众越集中，案例、标题和演示越容易让读者判断“这是否适合我”。

## 用户转化路径

1. **看到结果**：先展示修改前后页面和 [60 秒英文字幕静态导览](media/lecture-ppt-workflow-overview.mp4)，明确不是操作录屏。
2. **理解边界**：明确需要 Node、Python、中文字体和演示软件，并说明人工审核要求。
3. **低风险试用**：提供隔离安装命令和不依赖生成引擎的最小检查示例。
4. **完成首次成功**：让用户先复现短讲义示例，再处理自己的小章节。
5. **留下反馈**：用 Issue 模板收集环境、输入类型、结果和失败日志，不要求上传学生信息或未获授权的课件。
6. **形成复用**：把真实、脱敏的案例加入 README、示例或 Release 说明，推动下一轮传播。

## 发布资产

- 一个公开 GitHub 仓库和 `v0.1.0-alpha` Release。
- README 首屏：一句话定位、适用人群、最短检查步骤、前后对比图、限制和许可证，不承诺安装时长。
- 一个最小演示：短讲义、标准模板、修改前后课件、预览图和复现命令。
- 一个 60 秒视频：原创中文示例配英文字幕，展示输入标准、修改前后页面和反馈入口。
- 中文和英文各一版简介、Release 文案、FAQ 和问题反馈模板。
- 插件分发候选与可重复构建脚本：结构检查和应用内安装/触发分别记录，未完成后者不声称已验证。

## 四周节奏

### 第 1 周：降低首次试用门槛

完成公开仓库、隔离安装说明、最小示例、依赖诊断和限制说明。用第二台设备或干净环境验证安装与独立任务触发。

### 第 2 周：用结果吸引注意

发布一组前后对比图和短演示，围绕一个具体问题写内容，例如“如何把密集情境段落改成任务材料、问题和点击揭示分析”。每篇内容只放一个明确入口：试用示例或 GitHub。

### 第 3 周：获得真实案例

邀请少量教师或助教试用小章节。记录首次成功所需时间、失败点、修改轮次和他们愿意公开的反馈。不要把单个案例写成普遍效果承诺。

### 第 4 周：复盘与扩散

根据反馈修复安装、文档和触发问题；发布变更日志、已知限制和脱敏案例。再把稳定版本包装成插件或面向更大范围的公开发布。

## 适合使用的文案

**标题：** 把讲义和标准 PPT 变成可复用、可审核的教学课件工作流

**简介：** 面向教师与助教的 Codex Skill：结合讲义、标准课件和教师反馈，组织知识页面、授课备注、可编辑内容与点击动画，并提供索引、覆盖和样式检查。它保留人工审核，不承诺一键完成或跨软件完全兼容。

**行动号召：** 用短讲义复现最小示例；如果结果适合你的课程，再提交一份脱敏的环境和反馈记录。

## 需要持续观察的指标

- GitHub Traffic 的浏览/克隆统计与 Release 附件下载量，作为获取信号；不能直接当作用户人数。
- Issue 表单中自愿报告的安装成功、示例完成、实际制作和再次使用人数。
- 公开反馈中的常见失败点、修复版本及后续确认。

当前没有自动使用遥测、安装事件或链接点击统计。未获得完整分母时不计算“安装成功率”或“转化率”；自愿反馈也会有选择偏差。

下载量只能作为辅助指标；对这个 Skill，首次成功和重复使用更能说明推广是否有效。

## 当前必须诚实呈现的限制

仓库和 v0.1.0-alpha 已公开：[GitHub](https://github.com/hhhmike240-maker/lecture-ppt-workflow)。本分支准备 v0.1.1-alpha 双语候选；另一台电脑、独立 Codex 任务触发和英文课程输出尚未验证。Node、Python、中文字体以及演示软件会增加上手成本；跨平台、复杂模板和动态放映兼容性仍需单独验证。

上次 image-size 相关高危告警已在候选版本修复，新隔离安装审计为 0，见 [依赖与图片生成记录](DEPENDENCY_CHECK_20261004.md)。这不等于项目没有其他缺陷。
